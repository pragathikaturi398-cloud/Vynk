# Vynk REST API Documentation

## Base URL
`/api` or `http://localhost:5000`

---

## 1. Authentication (`/auth`)

### `POST /auth/register`
Register a new user (Student, Maintenance, Warden).
```json
{
  "name": "Aarav Sharma",
  "email": "student@vynk.local",
  "password": "password123",
  "role": "STUDENT",
  "roomId": "room-uuid"
}
```

### `POST /auth/login`
Authenticate with email and password. Returns JWT access token (15m expiry) and refresh token (7d expiry).
```json
{
  "email": "student1@vynk.local",
  "password": "password123"
}
```

### `POST /auth/refresh`
Refresh expired access token.
```json
{
  "refreshToken": "<refresh-token>"
}
```

### `GET /auth/me`
Fetches authenticated user profile, room allocation details, or assigned hostel.

---

## 2. Hostels & Infrastructure

- `GET /hostels`: List hostels with block and floor structure.
- `POST /hostels`: Create hostel (Warden / SuperAdmin).
- `GET /blocks?hostel_id=...`: List blocks.
- `GET /rooms?hostel_id=...&block_id=...`: List rooms.
- `GET /rooms/my`: Auto-detects the logged-in student's allocated room and hostel.
- `POST /room-allocations`: Assign student to room.

---

## 3. Categories & Teams

- `GET /categories`: List 8 core maintenance categories and subcategories.
- `POST /categories`: Create category (Admin).
- `GET /subcategories?category_id=...`: List subcategories.
- `GET /teams`: List 4 maintenance teams, lead technicians, and active load.

---

## 4. Complaints

### `POST /complaints` (multipart/form-data)
Submit a complaint. Returns immediately while triggering the AI triage pipeline.
- `room_id`: UUID of room
- `hostel_id`: UUID of hostel
- `title`: string
- `description`: string
- `attachments`: File(s) (JPEG, PNG, PDF up to 10MB)

### `GET /complaints`
Query parameters:
- `status`: SUBMITTED | AI_PROCESSED | NEEDS_REVIEW | ASSIGNED | IN_PROGRESS | ON_HOLD | RESOLVED | CLOSED
- `hostel`: Hostel UUID
- `category`: Category UUID
- `q`: Search query string
- `from`, `to`: Date filters

### `GET /complaints/:id`
Full details including:
- Room, block, and hostel hierarchy
- AI triage data (confidence, category, summary)
- Duplicate references
- Proof attachments
- Full event history & audit trail
- Student ratings

### `PATCH /complaints/:id/status`
State machine transition.
```json
{
  "status": "IN_PROGRESS",
  "note": "Technician on site inspecting MCB switch"
}
```

### `PATCH /complaints/:id/assign`
Manual assignment or category/severity override.
```json
{
  "team_id": "team-uuid",
  "assigned_to": "user-uuid",
  "severity": "CRITICAL",
  "note": "Elevated to Critical by Warden"
}
```

### `POST /complaints/:id/feedback`
Submit 1-5 star review and close ticket.
```json
{
  "rating": 5,
  "comment": "Repaired within 2 hours, excellent job!"
}
```

### `POST /complaints/:id/reopen`
Reopen ticket within 48 hours of resolution.
```json
{
  "reason": "Water leakage resumed after heavy rain."
}
```

## 5. Analytics & AI Insights

- `GET /analytics/overview`: High-level operations counters (Total, Open, SLA Breaches, Avg Resolution Time).
- `GET /analytics/by-hostel`: Hostel-level breakdown.
- `GET /analytics/by-category`: Category volume distribution.
- `GET /analytics/recurring`: Identifies rooms, blocks, or subcategories with repeated issues over the past 30 days.
- `GET /analytics/workload`: Team member active ticket distribution.
- `GET /analytics/resolution-time`: Average resolution hours per severity level.
- `GET /insights`: Latest plain-language summaries generated by Gemini.
- `POST /insights/generate`: Trigger on-demand Gemini AI insights analysis.
- `GET /reports/export?format=csv`: Download complete CSV operations report.

---

## 6. Audit Logs

- `GET /audit-logs`: Chronological immutable event stream of every state transition and action. Filterable by `complaint_id`.
